# English Dictation Model Selection — 21 November 2026

## Which models active open-source Mac dictation projects use or recommend

**Takeaway.** The current ecosystem converges on on-device Parakeet variants for fast local dictation, while offering WhisperKit, Apple Speech, Cohere, Moonshine, and streaming-specific engines as alternatives. An app's default is evidence of integration maturity, not independent proof that it is the most accurate.

**Cited findings.** TypeWhisper 1.8.2 lists Parakeet Ultra as its default, while exposing Parakeet v2/v3, WhisperKit, Apple SpeechAnalyzer, Cohere, Nemotron streaming, and other providers; its live preview is a separate WhisperKit path. [TypeWhisper](https://github.com/TypeWhisper/typewhisper-mac) Handy recommends Parakeet v3 for most users, but calls Cohere Transcribe its highest-accuracy English choice and Whisper Medium/Large an accuracy option for capable hardware. [Handy model guide](https://handy.computer/docs/models) OpenWhispr integrates Orukeet alongside Parakeet, Whisper, Cohere, and cloud providers. [OpenWhispr](https://github.com/OpenWhispr/openwhispr) Moonshine v2 offers small streaming models designed for live speech and makes a vendor benchmark claim against Whisper Large-v3; that is a project claim, not a matched Apple-Silicon comparison. [Moonshine v2](https://github.com/moonshine-ai/moonshine-v2)

VoiceInk remains an actively released local/cloud model hub: v2.21 added Parakeet Ultra and the latest listed release v2.27 adds ElevenLabs Scribe V3. These are model-provider options, not evidence that Ultra is the current VoiceInk default. [VoiceInk releases](https://github.com/Beingpax/VoiceInk/releases) WhisperKit is an Apple Core ML runtime for Whisper-family models, rather than a single fixed model; its design supports streaming partial transcription and model variants at different sizes. [Argmax WhisperKit](https://github.com/argmaxinc/argmax-oss-swift) [WhisperKit paper](https://arxiv.org/abs/2507.10860) FluidAudio's English Nemotron Speech Streaming 0.6B is a separate Core ML RNNT streaming option; its M5 Pro benchmark reports a 2.24-second default tier at 2.46% WER on a 100-file LibriSpeech sample, and a 1.12-second tier at 2.28%. [FluidAudio Nemotron streaming benchmark](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/Benchmarks.md)

**Inferences.** Competitor defaults establish that Ultra is production-integrated and that streaming commonly needs a distinct recognition path. They do not show that Ultra or any other option produces better text for Dictator's own microphone, speech, accent, cleanup, or insertion pipeline.

**Gaps.** Public competitor documentation does not provide one controlled, current, same-Mac, same-audio, same-normalizer trial across these engines. Several products combine model output with their own text normalization, vocabulary hints, and cleanup, so product-level quality cannot be attributed to the acoustic model alone.

## Does current evidence establish one best English model?

**Takeaway.** No. The strongest documented candidates are Parakeet Ultra for a mature high-accuracy batch path and Parakeet Unified for English streaming plus strong accuracy. Current public scores do not prove a real-microphone winner.

**Cited findings.** FluidAudio v0.18.4 contains the English `UnifiedModelFamily.parakeetEnglish` and supports both `UnifiedAsrManager` and `StreamingUnifiedAsrManager`; this is an official API in that release, but a dedicated Unified family/API rather than a case in the older `AsrModelVersion` enum. [v0.18.4 UnifiedConfig](https://github.com/FluidInference/FluidAudio/blob/v0.18.4/Sources/FluidAudio/ASR/Parakeet/Unified/UnifiedConfig.swift) [v0.18.4 streaming manager](https://github.com/FluidInference/FluidAudio/blob/v0.18.4/Sources/FluidAudio/ASR/Parakeet/Unified/StreamingUnifiedAsrManager.swift) On M5 Pro, FluidAudio reports Unified English LibriSpeech test-clean at 2.15% average / 1.68% aggregate WER in batch and 2.21% / 1.79% in streaming; the same documentation reports v3 at 2.6% average WER in that harness. Unified's default stream tier has 2.08 seconds of theoretical model look-ahead/chunk latency; 1.12-second and 0.32-second tiers are available with accuracy/throughput trade-offs. [FluidAudio benchmark and caveats](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/Benchmarks.md) FluidAudio's separate v3-family comparison reports Ultra at 2.13% test-clean and 3.81% test-other corpus WER, with approximately 630 MB download and 151× test-clean RTFx on M5 Pro; Ultra is a batch model. These scores use corpus-level WER, whereas Unified additionally reports per-file average WER, so the headline values are not a clean direct ranking. [FluidAudio v3/Ultra benchmark](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/Benchmarks.md)

Orukeet's self-published paired evaluation reports lower WER than its Parakeet baseline on FLEURS English (3.82% vs 4.28%) and a pooled English accent/domain set (8.84% vs 9.51%). The test-other score is not held-out evidence: the project says LibriSpeech test-other was used for final adaptation and checkpoint selection. The figures are reproducible claims from the project, not independent confirmation; the repo also links an OpenWhispr file-path comparison (11.40% vs 11.93%) but it is the same project's integration benchmark. [Orukeet evaluation and disclosed adaptation](https://github.com/Oruk-AI/orukeet/blob/main/docs/current-checkpoint-benchmarks.md) [Orukeet/OpenWhispr benchmark](https://github.com/Oruk-AI/orukeet/blob/main/integrations/openwhispr/APP_BENCHMARKS.md)

The FluidInference Hugging Face repo lists the Unified Core ML model under CC-BY-4.0 and shows an 11.2 GB total repository containing multiple model variants. That is the entire repository, not the selected runtime download. The v0.18.4 streaming loader requests only the configured encoder plus decoder, joint-decision model, and vocabulary; the default int8 streaming encoder bundle is listed as 592 MB, with the other required files adding a comparatively small amount. So a selected Unified configuration is roughly 0.6 GB to download, not an 11.2 GB bundled app. [FluidInference model card and variant list](https://huggingface.co/FluidInference/parakeet-unified-en-0.6b-coreml/blob/main/README.md) [Streaming loader](https://github.com/FluidInference/FluidAudio/blob/v0.18.4/Sources/FluidAudio/ASR/Parakeet/Unified/StreamingUnifiedAsrManager.swift) [Default int8 encoder size](https://huggingface.co/FluidInference/parakeet-unified-en-0.6b-coreml/tree/main/parakeet_unified_encoder_streaming_70_13_13_int8.mlmodelc)

There is a license provenance mismatch to resolve before redistributing weights: FluidInference's converted repository labels its model CC-BY-4.0, while a separate Core ML conversion of the same NVIDIA checkpoint identifies the upstream weights as governed by NVIDIA's Open Model License and specifies notice/attribution requirements. This is not enough to conclude the FluidInference conversion is wrongly labeled; it is enough to require checking the actual files and notices used by the app before distribution. [FluidInference license statement](https://huggingface.co/FluidInference/parakeet-unified-en-0.6b-coreml/blob/main/README.md) [NVIDIA-license conversion notes](https://huggingface.co/mattt/parakeet-unified-en-0.6b-coreml)

**Inferences.** Unified is the best-fit *candidate* if Dictator's target is one English model that can produce live partial text locally: it has a first-party streaming manager and a modest selected-model footprint. Ultra remains the stronger low-risk choice if the product can wait until speech ends and prioritizes the best documented v3-family batch WER. These are selection judgments based on different workflows, not proof Unified is more accurate than Ultra.

**Gaps.** FluidAudio's Unified results are developer benchmarks on M5 Pro/LibriSpeech, not an independent evaluation. Ultra and Unified have no public matched-mic or Indian-English head-to-head, no equivalent end-to-end live-dictation benchmark, and the stated 2.08 seconds is algorithmic look-ahead rather than measured spoken-word-to-visible-text latency. No source substantiates that either matches Wispr Flow quality for this user's voice.

## Which single model should Dictator evaluate next?

**Takeaway.** Evaluate one downloaded model only: Parakeet Unified EN 0.6B int8 streaming, default 2.08-second tier, with the 1.12-second tier as the latency comparison. Keep Ultra as the accuracy baseline in a temporary benchmark run only; do not ship or retain several models. Do not promote Unified as “best” until the user's actual workflow wins a controlled comparison.

**Cited findings.** FluidAudio v0.18.4 offers the Unified streaming route, uses the selected encoder variant rather than downloading all listed variants, and documents that the default tier uses 70/13/13 context (2.08 seconds theoretical latency); the lower-latency 70/7/7 option is 1.12 seconds. [Unified config](https://github.com/FluidInference/FluidAudio/blob/v0.18.4/Sources/FluidAudio/ASR/Parakeet/Unified/UnifiedConfig.swift) [Streaming model card](https://huggingface.co/FluidInference/parakeet-unified-en-0.6b-coreml/blob/main/README.md) Ultra's documented ~630 MB package is in the same rough deployment class as the selected Unified stream bundle, so the latter does not inherently impose a multi-gigabyte model install. [Ultra size and speed](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/Benchmarks.md) [Unified encoder size](https://huggingface.co/FluidInference/parakeet-unified-en-0.6b-coreml/tree/main/parakeet_unified_encoder_streaming_70_13_13_int8.mlmodelc)

OpenWhispr's Orukeet default is a real integration choice, but its published quality evidence is from the project team and includes test-set adaptation; it does not independently establish that Orukeet beats Unified or Ultra. [OpenWhispr](https://github.com/OpenWhispr/openwhispr) [Orukeet benchmark methodology](https://github.com/Oruk-AI/orukeet/blob/main/docs/current-checkpoint-benchmarks.md)

**Inferences.** Selection confidence: **high** that Unified EN is officially available in FluidAudio 0.18.4 and can run as a single on-demand local model; **medium** that it is the right architecture for Dictator's explicit English/live-preview goal; **low** that it is the most accurate option for this user, since matched real speech has not been scored. A short acceptance set should include this user's normal dictation, Indian-English/accented phrases, names and technical vocabulary, punctuation, corrections, and stop-to-final latency. Compare text exactly and measure audio-end-to-final-text and peak memory on the target Mac before making the default permanent.

**Gaps.** The app's capture, partial-text UI, post-processing, Accessibility insertion, and audio-end finalization can dominate perceived quality and latency. Model WER alone cannot verify those flows. The actual Mac model/hardware and on-device live samples are not available in this research brief; accordingly, this note recommends a focused evaluation, not a claim that the full app is now fixed or end-to-end proven.
