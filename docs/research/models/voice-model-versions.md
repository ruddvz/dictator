# Choose Speech Models With Measured Quality

> **Update — 21 November 2026:** The newer [English dictation model review](english-dictation-model-update-2026.md) supersedes the earlier recommendation below. Dictator's current source now uses FluidAudio 0.18.4 with one on-demand Parakeet Unified EN streaming configuration. This is the best current integration candidate for live English dictation, not a proven accuracy win over v2 or Ultra. The earlier comparison is retained as dated research; run a same-device corpus and live insertion acceptance before claiming an accuracy or end-to-end win.

> The analysis below is a **20 November 2026 snapshot**. Its package pin, model routing, and recommended bake-off describe the code at that time, not the current source.

At the time of that snapshot, Dictator should **keep its speech defaults until a same-device, same-audio benchmark proved a better replacement**. The analysis identified FluidAudio's Parakeet Ultra as an accuracy challenger and Moonshine Voice and NVIDIA's Nemotron streaming models as live-preview candidates. Wispr Flow's reported sub-700 ms end-of-speech latency was attributed to its cloud Canto model; its desktop app inserted completed transcripts after Stop rather than visibly streaming partial words. Published leaderboard and vendor figures were not interchangeable: runtimes, datasets, hardware, and normalization differed, and none tested the user's Dictator recordings.

## Parakeet v3 remains NVIDIA's current multilingual baseline

As checked on **November 20, 2026**, NVIDIA's catalog lists **Parakeet TDT 0.6B v3** as its current multilingual TDT checkpoint; the review found no NVIDIA-published v4. The v3 model card describes automatic recognition across 25 European languages with punctuation, capitalization, and timestamps. NVIDIA also lists English 1.1B models, Japanese and Vietnamese checkpoints, and a smaller streaming EOU model, but these are distinct options rather than newer v3 replacements. ([NVIDIA NeMo checkpoints](https://docs.nvidia.com/nemo/speech/nightly/asr/asr_checkpoints.html), [featured models](https://docs.nvidia.com/nemo/speech/nightly/asr/featured_models.html), [v3 model card](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3))

FluidAudio's newer **Ultra** and **Redux** are derivatives of v3, not NVIDIA Parakeet generations. FluidAudio's Core ML benchmark on an M5 Pro reports Ultra's word error rate (WER) below v3 on LibriSpeech clean/other (2.13%/3.81% versus 2.27%/4.12%) and its 24-language FLEURS average (11.67% versus 14.81%), with roughly similar short-clip speed. These are FluidAudio's vendor-run measurements, not Dictator results. Ultra is about 630 MB and supports macOS 14+. Redux is about 220 MB but has worse English WER than v3 and reports several minutes of first-use Neural Engine compilation, so it is a download-size option rather than the accuracy default. ([FluidAudio benchmarks](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/Benchmarks.md), [Ultra details](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/ASR/ParakeetUltra.md), [Ultra model card](https://huggingface.co/FluidInference/parakeet-ultra-coreml), [Redux model card](https://huggingface.co/FluidInference/parakeet-redux-coreml))

The snapshot's source pinned **FluidAudio 0.18.2**. At that point FluidAudio 0.18.4 was newer, and the review had not found a Parakeet-specific accuracy gain in its release notes. Ultra was supported by earlier FluidAudio APIs, so the recommendation was to evaluate the model separately. ([Dictator package pin](../../../Packages/DictatorParakeet/Package.swift), [FluidAudio releases](https://github.com/FluidInference/FluidAudio/releases), [Ultra support release](https://github.com/FluidInference/FluidAudio/releases/tag/v0.17.3))

## Streaming models target a different problem than a better batch checkpoint

For words that appear while the user is still speaking, the relevant comparison is a **streaming recognizer**, not merely a more accurate batch Parakeet. NVIDIA's Nemotron 3.5 ASR Streaming 0.6B supports 40 locales and automatic language detection, and NVIDIA's NeMo-Speech.cpp offers Apple-Silicon Metal builds. Its published chunk-latency table, however, is for a different English streaming model and tests Intel CPU/NVIDIA GPU hardware—not Apple Silicon. The runtime is Apache-2.0, while Nemotron 3.5's model weights use the separate OpenMDW-1.1 license. Any redistribution must review both. ([NVIDIA model guide](https://docs.nvidia.com/nemo/speech/nightly/starthere/choosing_a_model.html), [NeMo-Speech.cpp models](https://github.com/NVIDIA/NeMo-Speech.cpp), [macOS installation](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/install.md), [OpenMDW license](https://openmdw.ai/license/1-1/))

**Moonshine Voice is a lower-friction Swift prototype candidate** because its official quickstart exposes microphone callbacks and its models include English streaming sizes from 34M to 245M parameters. Moonshine reports a 6.65% eight-dataset WER for its Medium streaming model and says speculative decoding reduced its own MacBook Pro finalization latency from about 103 ms to 74 ms. These are Moonshine's measurements; their dataset count differs from the NVIDIA nine-set comparison and the timings are not a Dictator-device result. ([Moonshine Swift quickstart](https://github.com/moonshine-ai/moonshine/blob/main/docs/quickstart.md), [models](https://github.com/moonshine-ai/moonshine/blob/main/docs/models/available-models.md), [changelog](https://github.com/moonshine-ai/moonshine/blob/main/CHANGELOGS.md), [benchmark method](https://github.com/moonshine-ai/moonshine/blob/main/docs/using/benchmarks.md))

Other options solve different needs. Qwen3-ASR offers 0.6B and 1.7B models, automatic language detection, 30 languages plus 22 Chinese dialects, and offline/streaming inference, but its official stack is Python/PyTorch rather than a native Swift/Apple Neural Engine runtime. Whisper large-v3 Turbo is a practical file-transcription option through the Argmax Swift SDK; OpenAI's cited 8× speed claim is on an A100, not a Mac. Argmax's SDK 1.0.0 includes breaking API changes and renames the former WhisperKit package, so upgrading it is independent of selecting a new live engine. ([Qwen3-ASR repository](https://github.com/QwenLM/Qwen3-ASR), [OpenAI Whisper](https://github.com/openai/whisper), [Argmax SDK model list](https://github.com/argmaxinc/argmax-oss-swift/blob/main/README.md), [Argmax 1.0 release](https://github.com/argmaxinc/argmax-oss-swift/releases))

## Wispr Flow's Canto is fast cloud recognition plus a separate editing layer

Wispr says desktop Flow now uses its proprietary **Canto** model, trained on millions of hours of speech and text and tuned with supervised training and reinforcement learning. It reports a latency budget below **700 ms from end of speech to visible text**, including recognition, formatting, operating-system, and network time; after replacing an earlier multi-recognizer ensemble, it reports a 54% drop in desktop dictations taking over one second. These are Wispr's production metrics, not independently reproduced benchmarks. Canto's architecture, parameter count, model weights, and full training corpus are not public. ([Canto overview](https://wisprflow.ai/canto), [Canto 1 results](https://wisprflow.ai/canto-1-results))

“Real-time model” does not mean Flow visibly streams partial words into the desktop field: Wispr's help page says desktop transcription requires internet and inserts the completed transcript after Stop. Its quality layer includes configurable None/Light/Medium cleanup, undo/redo for AI edits, contextual hints from readable active fields, app/site categories, and a personal dictionary with explicit spelling and correction entries. Wispr reports a 13% reduction in desktop dictation edit rate after Canto 1; it also says the more selective correction-learning method discussed in its research is future-facing, not already deployed in Canto 1. ([Flow help](https://docs.wisprflow.ai/articles/2772472373-what-is-flow), [cleanup settings](https://docs.wisprflow.ai/articles/4283510616-Auto-Cleanup:-control-how-much-Flow-edits-your-dictation), [context awareness](https://docs.wisprflow.ai/articles/4678293671-Context-Awareness), [dictionary](https://docs.wisprflow.ai/articles/4052411709-teach-flow-your-words-with-the-dictionary), [Canto 1 results](https://wisprflow.ai/canto-1-results))

Flow processes audio on Wispr's servers. This may help its centralized model iteration, but it changes privacy and network assumptions; it should not be treated as a drop-in replacement for Dictator's local engines. Dictator can borrow the user-visible controls—cleanup strength, raw-versus-cleaned transcript, undo/redo, explicit correction learning—without adopting cloud recognition. Wispr's own launch evaluation also shows why quality claims need context: its test sets and public leaderboard results did not establish a universal win across languages and speech conditions. ([Wispr security and privacy](https://wisprflow.ai/dictation-blogs/is-wispr-flow-safe-security-and-privacy), [Canto evaluation](https://wisprflow.ai/canto))

## Pipeline assessment at the time of the earlier comparison

At that snapshot, **Apple Speech** provided on-device partial text while speaking; optional **Parakeet TDT** ran locally through FluidAudio/Core ML after key release, with v2 used for English and v3 for multilingual routing. WhisperKit/Argmax was a separate file-transcription path, not the live microphone path. That led to the recommendation to prototype a streaming engine rather than only swap a batch checkpoint. ([Mic transcriber](../../../Dictator/Speech/MicTranscriber.swift), [Parakeet engine](../../../Dictator/Speech/ParakeetDictationEngine.swift), [Parakeet wrapper and pin](../../../Packages/DictatorParakeet/Package.swift), [file transcriber](../../../Dictator/Speech/WhisperKitFileTranscriber.swift))

The first model experiment should make **Ultra an optional local challenger** while preserving v2/v3, then compare every path on identical held-out Dictator audio. If the goal is visible partial text with another model, prototype Moonshine and Nemotron streaming separately; Moonshine has a direct Swift path, while Nemotron has a more involved C++/Metal integration and a licensing review. Qwen3-ASR is a reasonable offline evaluation candidate for language coverage, but not the lowest-risk native Mac integration. Do not select Redux as the quality default or promote a 30B cloud/server model on leaderboard position alone.

The quality gate must measure more than WER. Use a fixed, consented local corpus covering spontaneous short phrases, Indian English accents, proper names, technical vocabulary, code-switching, noisy and quiet speech, numbers, punctuation, and correction rules. Record WER/CER where appropriate, proper-name recall, false personalization changes, end-of-speech-to-insert p50/p95, first-use compilation, warm latency, peak memory, CPU/Neural Engine use, energy, and exact-once insertion. Pin model checksum, runtime version, decoding parameters, device and test-corpus version; otherwise an apparent improvement may come from a changed test set rather than a better model.

## Conclusion

Review upstream model and runtime changes monthly, but promote them only after the same benchmark passes against the last known-good release. Keep candidates optional during evaluation, retain a rollback path, verify licenses and redistribution terms, and never silently fall back to cloud recognition. That policy lets Dictator adopt real quality or latency gains without making the user pay for a new default in privacy, insertion reliability, memory, battery, or language regressions.
