# HushKey project audit — 2026-11-08

## Result

The repository builds and its local automated suite is green. This is **not** a 100% end-to-end sign-off: live microphone, system-audio, headphone motion, and several complete UI journeys remain unverified. The screen layouts are consistent, but the repeated card grids and quiet empty states still read generic. This audit adds HushKey's existing voice-ribbon mark to each section title as a first identity improvement; a broader visual pass remains open.

## Findings

| Severity | Finding and reproduction | Resolution |
| --- | --- | --- |
| P1 | **Cross-app insertion could miss the focused field.** Focus a supported non-secure field in another app and dictate. The system-wide Accessibility query could return no focused value, so HushKey offered Copy instead of typing. | Fixed in `HushKey/Services/TextInsertionService.swift:757`: prefer the target application's focused element, then fall back to system-wide/frontmost candidates; reject candidates from a different process. Four resolver tests cover candidate selection. A no-microphone rehearsal visibly inserted text into a separate blank macOS app. |
| P2 | **Silent Use could retain a latent direct-typing preference.** Turn global typing off while “Type into the front app” is saved on, then later re-enable global typing. The old UI allowed the preference to be armed while typing was unavailable. | Fixed in `HushKey/Views/Lab/UseView.swift:126`: explain the saved state and allow clearing it, while disabling an off preference until global typing is enabled. The rendered page was reviewed in light and dark snapshots. |
| P2 | **The hub's shared card language looked generic.** Switch through section titles and empty states; repeated cards had little HushKey-specific signature. | First improvement in `HushKey/Views/Components/Components.swift:18`: use the existing animated voice ribbon beside every section title. The broad card/empty-state visual direction is still open and needs user review. |
| P2 | **Device-specific end-to-end coverage is incomplete.** Exercise microphone dictation, Meetings system audio, file import through export, live headphone capture, and silent-use insertion. These flows were not run with real devices during this audit. | Open verification gap. Unit tests and empty-state screenshots do not prove device behavior. Complete the live acceptance steps with the user and record results in `docs/TESTING_PROTOCOL.md`. |
| P3 | **Shortcut capture had a Swift 6 actor-isolation warning.** Build the shortcut recorder in Swift 6 mode. | Fixed in `HushKey/Views/Components/ShortcutRecorder.swift:56`: copy event primitives before entering the main-actor block; do not send `NSEvent` across the actor boundary. `ShortcutConflictTests` is explicitly main-actor isolated. |
| P3 | **Labels and help text differed across screens.** Compare connection naming, the hands-free gesture, history deletion, typing fallback, and the paste-again card. | Normalized wording in `HushKey/App/AppModel.swift:30`, `HushKey/Views/Hub/SettingsView.swift`, `HushKey/Views/Hub/DictationView.swift`, `HushKey/Views/Hub/StyleView.swift`, and `HushKey/Views/Pill/FloatingPill.swift`. Updated README and design/testing docs to match current UI labels. |

Static control review found no enabled button with an empty action or shipping placeholder. History's unavailable action is disabled and explains why. Secure fields remain rejected by the insertion service. Static review is not a substitute for clicking every control in the live app.
