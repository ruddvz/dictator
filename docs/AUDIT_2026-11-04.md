## 2. Findings & Fixed Defects

### Defect 1: Click Swallowing on Transparent Floating Pill Window Regions
- **Severity:** P1 (UX / Interaction Blocker)
- **File & Line:** `Dictator/Views/FloatingPill.swift:230-297`
- **Description:** The floating pill window is a non-activating `NSPanel` fixed to at least 220 × 84 pt to prevent window resize jumps. However, Cocoa `NSHostingView` by default intercepts mouse down events over its entire bounds, even where the background is completely transparent (`Color.clear`). Clicking just above the idle pill swallowed clicks meant for underlying applications.
- **Fix:** Implemented `PillInteractiveHosting` protocol and customized `FirstMouseHostingView.hitTest(_:)` to check against `activeContentRect`. Any click falling outside the measured content capsule returns `nil`, seamlessly passing through to the underlying application.
- **Test:** Added `PillHitTestTests.testClicksOutsideActiveContentRectPassThrough` in `DictatorTests/PillPlacementTests.swift`.

---

### Defect 2: Dictation Generation Race Condition on Superseded Starts
- **Severity:** P1 (Audio / State Race)
- **File & Line:** `Dictator/App/AppModel.swift:2111-2180`
- **Description:** If a user rapidly triggered or cancelled dictation (incrementing `dictationStartGeneration`), an asynchronous start task awaiting `audio.start()` or `speechPreparation` could resume after being superseded. It would then execute failure cleanup, tearing down the running audio engine of the *new* generation and releasing the shared `captureGate`.
- **Fix:** Added strict `guard generation == dictationStartGeneration` checkpoints immediately following `audio.start()`, `speechPreparation`, and `speechStart`. If superseded, the task logs `"superseded"` and returns immediately without touching running audio, preview transcribers, or the capture gate.

### Defect 3: Audio Engine Shutdown Racing Fast Hardware Restart
- **Severity:** P1 (CoreAudio / Hardware Crash Risk)
- **File & Line:** `Dictator/Audio/AudioService.swift:34-110`
- **Description:** `AudioService` operations are serialized on `engineQueue`. However, rapid start/stop calls could leave hardware taps installed or attempt to bind a new input tap while the previous `AVAudioEngine` was still shutting down, leading to CoreAudio node bus crashes or silent recording streams.
- **Fix:** Introduced `private static var activeEngine: EngineBox?` tracked on `engineQueue`. When `start()` runs, any existing active engine is cleanly stopped, detached, and destroyed prior to initializing the new engine. Also added a direct synchronous fast-path check for `AVCaptureDevice.authorizationStatus(for: .audio) == .authorized` to prevent asynchronous hop latency.

---

### Defect 4: Synchronous Main-Thread Stall from Foundation Model Prewarming
- **Severity:** P2 (Performance Hitch)
- **File & Line:** `Dictator/App/AppModel.swift:2145-2158`
- **Description:** Starting dictation called `DictationSmartCleanup.prepare()`, which synchronously initialized Apple Intelligence language model sessions on the main actor, causing a 16–36 ms stall during the critical key-down audio capture path.
- **Fix:** Moved `DictationSmartCleanup.prepare()` into a detached `@MainActor` Task executed asynchronously while audio capture buffers. Dictation start latency dropped by ~22 ms without delaying cleanup readiness for the finished utterance.

---

### Defect 5: Premature Stop on Fast `fn` Key Taps
- **Severity:** P2 (Dictation Drop)
- **File & Line:** `Dictator/App/AppModel.swift:2040-2055`
- **Description:** Releasing `fn` quickly (under 150 ms) triggered `stopWhileStarting()` while `audio.start()` was still in flight, leaving `stopsWhenStarted` unasserted if `audio.isRunning` had not flipped to true yet. This resulted in an orphaned dictation that either ignored the stop or dropped the utterance.
- **Fix:** Updated `stopWhileStarting()` to set `stopsWhenStarted = true` whenever `audio.isRunning || audio.isStarting`, guaranteeing clean finalization once the audio session completes opening.

### Defect 6: Dock Activation Policy Flicker when Opening Settings or Sheets
- **Severity:** P2 (Visual Glitch)
- **File & Line:** `Dictator/App/DictatorApp.swift:80-145`
- **Description:** In menu bar mode (`showsInDock == false`), opening Settings or presenting/dismissing modal sheets triggered `NSWindow.willCloseNotification` or delayed key window notifications. If `isHubWindowOpen` momentarily flapped to `false`, macOS would abruptly revoke the Dock icon and menu bar, causing screen flicker and lost focus.
- **Fix:**
  1. In `observeHubWindows()`, explicitly guarded with `window.sheetParent == nil`. Sheets closing or opening never flap the Hub window's visibility state.
  2. In `MenuBarLabel.task`, set `model.isHubWindowOpen = true` synchronously prior to `openWindow(id: "main")`, ensuring the window opens directly under `.regular` activation policy without mid-transition layout switching.

### Defect 7: Secure Text and Password Field Insertion Protection
- **Severity:** P1 (Security / Privacy)
- **File & Line:** `Dictator/Services/TextInsertionService.swift:58-95`
- **Description:** Accessibility inspection for text fields did not adequately reject custom secure text fields or password inputs where subrole attributes were formatted as `AXPasswordField` or marked with `AXIsPassword`.
- **Fix:** Hardened `isSupportedTextTarget(role:subrole:)` and `isSupportedPasteTarget(role:subrole:)` to check for case-insensitive substrings `"secure"` and `"password"`. Added inspection of `AXIsPassword` attribute, and ensured `nearbyContextHints()` safely returns empty arrays on password fields.
- **Test:** Added `InsertionSecureFieldTests` in `DictatorTests/PillPlacementTests.swift` verifying rejection of `AXSecureTextField`, `AXPasswordField`, and acceptance of normal fields.

---

### Defect 8: Ambient Field Render Server CPU Consumption at Idle
- **Severity:** P2 (Battery / Background CPU)
- **File & Line:** `Dictator/Views/Ambient.swift:210-245`
- **Description:** `AmbientField` pauses animations when hidden, but closing the Hub window did not immediately propagate window closure to the embedded `ReaderView` until garbage collection or subsequent visibility events occurred.
- **Fix:** Added an observer for `NSWindow.willCloseNotification` inside `ReaderView.makeNSView` to immediately invoke `reportClosed()` and pause all CoreAnimation layers.

---

### Defect 9: Multi-Display Reconfiguration & Dock Repositioning
- **Severity:** P2 (Window Placement)
- **File & Line:** `Dictator/Views/FloatingPill.swift:45-155`
- **Description:** Connecting external monitors or moving the macOS Dock to the left or right side of the screen left the floating pill placed at stale coordinates or off-screen.
- **Fix:** Observed `NSApplication.didChangeScreenParametersNotification` in `FloatingPillController` to validate the active screen against `NSScreen.screens`, fall back to `screenUnderPointer()`, and re-calculate `place()`.
- **Test:** Added `testDockOnLeftAdjustsVisibleMinX` and `testDockOnRightAdjustsVisibleWidth` in `PillPlacementTests.swift`.

---

### Defect 10: Crash Safety & Directory Creation in Local JSON Archives
- **Severity:** P2 (Data Integrity)
- **File & Line:** `Dictator/Recording/LocalJSONArchive.swift:41-70`, `SessionRecorder.swift:115-125`
- **Description:** `LocalJSONArchive.save` and `replaceAfterExplicitRecovery` called `data.write(to: url, options: .atomic)` directly. If the application support directory or parent folders were missing (e.g. fresh installation or storage cleanup), writes threw Cocoa error 4. `SessionRecorder` wrote `meta.json` without atomic options.
- **Fix:** Added automated intermediate directory creation (`fileManager.createDirectory(at: directory, withIntermediateDirectories: true)`) before writing in `LocalJSONArchive`, and added `.atomic` writing options to `SessionRecorder`.

---

### Defect 11: Termination Data Loss on Pending History Saves
- **Severity:** P2 (Data Loss)
- **File & Line:** `Dictator/App/AppModel.swift:2550-2565, 3140-3150`
- **Description:** History saves are debounced by 0.5 s via `dictationHistorySaveTask`. If Dictator quit immediately after a dictation, `prepareForTermination()` cancelled the save task without flushing, losing the last transcript.
- **Fix:** Added `flush: Bool = false` parameter to `cancelPendingDictationHistorySave(flush:)` and invoked it with `flush: true` in `prepareForTermination()`, ensuring pending entries are written synchronously to disk on application exit.

---

### Defect 12: Elevated TypeWhisper-Style Menu Bar Menu & Live Glyph
- **Severity:** P2 (Product Feature / Usability)
- **File & Line:** `Dictator/App/DictatorApp.swift:145-310`, `AppModel.swift:2640-2675`
- **Description:** Users requested TypeWhisper lightness — the ability to control and monitor Dictator entirely from the menu bar without ever needing the main window open.
- **Enhancement:**
  - **Dynamic Status Line:** Real-time state ("Listening…", "Transcribing…", "Opening microphone…", "Shortcuts paused", "Dictator · Ready").
  - **Live Glyph Indicator:** Sage circle dot in menu bar during active recording, slate dot during transcription.
  - **Hardware & Engine Submenus:** Quick-switch Microphone, Language, and Engine (Parakeet / Apple Speech) directly from the menu bar.
  - **Quick Actions:** Direct shortcuts to History, Transcribe audio file, Recover last recording, Copy last transcript to clipboard, and Pause global shortcuts.
